# 闸口事件湖仓台

码头闸口扫描先落在贴源层，原文照收。建层员选定业务日，按事件字典把扫描收成明细层：进闸、出闸、倒箱。字典里没有的事件码、时间读不出的扫描留在剔除清单，不进明细。

箱号不是四位字母加七位数字时，各闸口不许各自处理：当天先写定唯一补码办法，坏号统一进坏号队列，按办法处理后再收成。

## 补码办法

每个业务日只能二选一，写定后**本日不许改口**：

| 办法 | 含义 |
|------|------|
| 队列拦收 `queue_block` | 坏号挡在坏号队列，不收成、不进明细 |
| 缺位补位 `pad_to_detail` | 保留原文只补缺位，补成合规箱号后再入库到明细（明细标记“已补位”） |

规矩：

- 收成请求必须带办法；与当天设置对不上的扫描记“补码办法不符”，该条不准写入明细。
- 补码办法未写定时，坏号不准收成，记“补码办法未写定”。
- 箱号全空的扫描直接剔除，不进坏号队列。
- 两个作业员抢同一条坏箱号：队列行加锁，只放行与办法相符的第一记，后到的记“补码争用”。
- 补成箱号必须仍是四位字母加七位数字，且保留原文箱号、只补缺位。

## 页面

| 页面 | 内容 |
|------|------|
| 补码设置 | 写定/查看当天办法，写定后锁定 |
| 坏号队列 | 待处理坏号、剔除次数、拦收/补位操作、已处理记录、补码台账（办法不符与争用留痕） |
| 箱号列表 | 坏号、剔除次数、补成次数、办法名、状态 |
| 补码详情 | 分“已合规”和“已补位”，对照原文箱号与补成后的箱号 |
| 贴源 / 明细 | 原文扫描、明细层（带来源标记）、剔除清单 |

## 接口一览

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/dates/<biz_date>/box-policy` | 写定当天补码办法（改口返回 409） |
| GET | `/api/dates/<biz_date>/boxes` | 箱号列表、坏号队列、补码台账、补码详情 |
| POST | `/api/dates/<biz_date>/completions` | 拦收/补位一条坏号（办法不符 409、争用 409） |
| POST | `/api/dates/<biz_date>/build` | 带办法收成明细层 |
